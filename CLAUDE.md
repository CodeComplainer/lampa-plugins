# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Публичный репозиторий плагинов для [Lampa](https://github.com/yumata/lampa-source) —
медиацентра для ТВ. Здесь лежат **собранные** `.js`-файлы, которые Lampa загружает по URL.

Плагины пишутся под LG webOS, область — **только торренты** (онлайн-балансеры не используются).

## Как это подключается

Lampa хранит список плагинов в localStorage под ключом `plugins` — массив `{url, status}`.
Раздача идёт через **GitHub Pages** (ветка `main`, корень репозитория):

```
https://codecomplainer.github.io/lampa-plugins/<плагин>.js
```

**`raw.githubusercontent.com` использовать нельзя.** Проверено: raw отдаёт файл как
`content-type: text/plain` вместе с `x-content-type-options: nosniff`, поэтому браузер
отказывается исполнять его как скрипт — тег `<script>` завершается ошибкой, плагин
молча не загружается. Pages отдаёт `application/javascript`, и всё работает.

Репозиторий обязан быть публичным: у приватного Pages не работает, а raw требует токен.

Установка на телевизор — через плагин-менеджер (см. ниже), вводить адреса вручную не нужно.
Штатная «Удалённая конфигурация» Lampa для этого не подходит: она выдаёт пятизначный код
и умеет принимать команды `{type:'extension', url}`, но **отправляющей стороны нет** —
перебор `send`, `set`, `add`, `install`, `push` на `cub.rip/api/remote-configuration/`
даёт 404, реализован только приём.

## Разработка

Исходники плагинов живут **не здесь**, а в рабочей копии Lampa, в `plugins/<имя>/` —
там же собираются. Точный путь смотри в `CLAUDE.local.md` (не в git).

Цикл:

```bash
node tools/plugin-dev.js <имя> --watch   # в репозитории Lampa, пересборка ~2 с
npx vitest run plugins/<имя>/            # тесты плагина
```

Готовый файл из `build/web/plugins/<имя>.js` копируется в корень этого репозитория
и коммитится. **Перед копированием стоит удалить старый бандл и пересобрать заново:**
сборщик несколько раз отдавал устаревший результат (в бандл попадал вызов функции
без её определения).

Push делать через PowerShell — из Bash git-авторизация не проходит.

## Соглашения

- **Conventional commits**, сообщения — **на английском**: `feat:`, `fix:`, `docs:`, `chore:`.
- Комментарии в коде — на русском, как в самой Lampa.
- Стиль кода Lampa: без точек с запятой, отступ 4 пробела, jQuery (`$`) как глобальный.
- Плагин обязан иметь защиту от повторной инициализации: `window.plugin_<имя>_ready`.
- Взаимодействие с приложением — только через глобальный `window.Lampa`.

## Тесты

Тесты живут рядом с исходниками плагина (`plugins/<имя>/*.spec.js`, vitest).

**Названия фильмов и сериалов в тестах — вымышленные** (`Movie Name`, `Series Name`,
`Anime Title`). Настоящими остаются только названия студий озвучки: это справочные
данные, без них невозможно проверить распознавание.

Своя реализация разбора названий нужна потому, что штатный `TitleParser` Lampa
имеет три дыры, а править апстрим мы не можем: `CAMRip`/`TSRip` не распознаются,
кириллическая «х» в `03х01` даёт первый сезон вместо третьего, `HDR10+` не считается
за HDR.

## Как добавить новый плагин

### 1. Исходники

Создать `plugins/<имя>/<имя>.js` в рабочей копии Lampa. **Имя файла обязано совпадать
с именем папки** — так устроена сборка. Рядом кладутся вспомогательные модули и тесты.

Скелет:

```js
function startPlugin(){
    if(window.plugin_<имя>_ready) return   // защита от повторной инициализации

    window.plugin_<имя>_ready = true

    // регистрация кнопок, экранов, настроек
}

Lampa.Lang.add({
    <имя>_title: {ru: '…', en: '…', uk: '…'}
})

if(window.appready) startPlugin()
else Lampa.Listener.follow('app', (e) => { if(e.type === 'ready') startPlugin() })

export default {}
```

Полезно вынести отладочный доступ: `window.__<имя> = {…}` — тогда логику можно
прогонять на живых данных прямо из консоли браузера, не пересобирая.

Чистые функции (разбор, отбор, решения) держать в отдельных модулях и покрывать
тестами; в основном файле оставлять UI и оркестрацию.

### 2. Сборка и проверка

```bash
npx vitest run plugins/<имя>/
rm -f build/web/plugins/<имя>.js && node tools/plugin-dev.js <имя>
```

Линт и форматирование — [Biome](https://biomejs.dev), запускается из этого репозитория:

```bash
npm run lint      # проверить
npm run format    # исправить и отформатировать
```

Конфиг лежит здесь (`biome.json`), а исходники — в рабочей копии Lampa, поэтому
скрипты запускают Biome оттуда через `--config-path`: сам он за пределы своего
корня не выходит.

Несколько правил отключено осознанно, это не небрежность:

| Правило | Почему выключено |
|---|---|
| `useConst` | в самой Lampa везде `let`, плагины должны читаться как её код |
| `noAssignInExpressions` | `if((m = str.match(…)))` — обычная идиома разбора регулярками |

Форматирование Biome ставит пробел после `if` и `function` — это расходится
со стилем Lampa (`if(...)`), но отключить нельзя. Приняли как плату за
единообразие внутри плагинов.

Удалять бандл перед сборкой обязательно: сборщик несколько раз отдавал устаревший
результат — в бандл попадал вызов функции без её определения, и плагин падал
с `… is not defined`.

Проверка в браузере (параметр `v` обходит кеш):

```js
localStorage.setItem('plugins', JSON.stringify([
    {url: 'http://localhost:3000/plugins/<имя>.js?v=' + Date.now(), status: 1}
]))
```

Проверять **до** публикации: на телевизоре отлаживать несравнимо дольше.

### 3. Публикация

```bash
cp build/web/plugins/<имя>.js ../lampa-plugins/<имя>.js
```

Затем добавить запись в `plugins.json` — иначе плагин не появится в менеджере:

```json
{"file": "<имя>.js", "name": "Короткое название", "descr": "Что делает"}
```

Необязательные поля:

| Поле | Смысл |
|---|---|
| `replaces` | имена файлов, которые этот плагин заменяет — переименование переезжает само |
| `default` | `false` — не ставить автоматически при появлении в манифесте |
| `local` | `true` — плагин не публикуется и виден только в режиме локального сервера |

`name` и `descr` видны на телевизоре в разделе «Мои плагины», поэтому пишутся
для пользователя, а не для разработчика. Сам `manager.js` в манифест не вносится —
см. раздел о менеджере ниже.

Коммит и `git push` **через PowerShell**. GitHub Pages обновляется не мгновенно —
обычно до минуты. Проверить, что раздача поднялась и MIME правильный:

```bash
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" \
  https://codecomplainer.github.io/lampa-plugins/<имя>.js
```

Должно быть `200 application/javascript`. Если `text/plain` — значит адрес указывает
на raw, и плагин не запустится.

На телевизоре ничего вводить не нужно: менеджер подтянет новый плагин из манифеста
сам, останется включить переключатель.

## Плагины

### manager.js — менеджер плагинов

Единственный плагин, адрес которого приходится вводить на телевизоре. Дальше все
остальные включаются переключателями в настройках, раздел «Мои плагины».

- Список берётся из `plugins.json` в корне репозитория — новый плагин появляется
  на телевизоре сам, достаточно добавить строку в манифест. Манифест перечитывается
  при каждом заходе в настройки; момент — открытие **главного** экрана настроек,
  а не нашего раздела: параметры раздела собираются при его создании, и
  перерисовывать их, когда он уже на экране, поздно.
- Список плагинов приводится в соответствие манифесту: новый ставится сам,
  переименованный переезжает по `replaces` (и только если старый стоял — иначе это
  была бы установка без спроса), исчезнувший удаляется. Трогаются только свои адреса:
  плагины, добавленные мимо менеджера, не наше дело.
- Ключ `manager_seen` помнит, что менеджер уже предлагал. Без него пришлось бы выбирать
  между «новые плагины не появляются» и «выключенные возвращаются при каждом запуске».
- Переключатель источника **GitHub / локальный сервер**: в локальном режиме плагины
  грузятся с машины разработчика (`http://<ip>:3000/plugins/`), что позволяет проверять
  свежую сборку на телевизоре без публикации. Режим проверен целиком: плагин реально
  загружается с локального адреса и работает.
- Под каждым плагином показан фактический адрес загрузки.

**Сам менеджер в `plugins.json` не добавляется намеренно.** Иначе его можно выключить
переключателем и остаться без доступа к остальным плагинам — вернуть их можно будет
только вводом адреса пультом.

**Про локальные адреса.** `addPluginParams` ([plugins.js:148](src/core/plugins.js:148))
пропускает всю обработку для URL с IP-адресом. Отсюда два следствия:

- `Utils.rewriteIfHTTPS` к таким адресам не применяется, поэтому локальный режим
  переживает ситуацию, когда сама Lampa открыта по https — иначе адрес переписался бы
  и сборка перестала грузиться;
- но и `reset=Math.random()` не добавляется, то есть штатного обхода кеша нет.
  Dev-сервер отдаёт `Cache-Control: max-age=0` с ETag, поэтому в браузере свежая сборка
  подхватывается. Если на webOS правки перестанут появляться после пересборки —
  причина в кеше, и нужно добавлять метку версии к локальным адресам.

Порядок важен: автоустановка выполняется **до** отрисовки настроек, иначе переключатель
запомнит состояние «выключен», которое было до установки. Значение переключателя при
каждой отрисовке приводится к факту (`Lampa.Storage.set`), потому что плагин могли
добавить или удалить мимо менеджера.

### memory.js — память просмотра

Тайтл включается так же, как в прошлый раз: по тому же названию, с той же
озвучкой и теми же субтитрами. Работает при любом запуске плеера и на обычном
экране торрентов, а не только через кнопку `continue.js` — поэтому отдельный плагин.

**Название для поиска.** Название карточки и трекерное совпадают не всегда:
корейский сериал «Суперчудаки» (원더풀스) лежит на трекерах как «Суперглупцы»,
и ни одно из названий карточки не находит ничего. Плагин подставляет запомненное
название в штатный экран торрентов на событии `activity`/`init` — оно приходит
после создания компонента, но до начала поиска.

- Запоминается по факту **запуска файла**, а не удачного поиска: «нашлось»
  и «это то, что нужно» — разные вещи.
- Хранится только нестандартное название: то, что и так строится из карточки,
  занимало бы место впустую.
- Дублируется в штатный `user_clarifys` — он синхронизируется через CUB и читается
  обычным списком уточнения ([filter.js:36](src/interaction/filter.js:36)), поэтому
  правильное название всплывает первым и на другом устройстве. Заодно карточка
  подрезается до пяти запросов: штатный код пишет туда без ограничений.
- Если своей записи ещё нет, берётся последнее, что человек вводил руками.

**Озвучка и субтитры.**

- Дорожки сопоставляются по языку и названию, **не по индексу**: в одной раздаче
  русская дорожка первая, в другой третья.
- Совпадение названия озвучки важнее языка — «Дубляж» и «LostFilm» обе русские,
  но выбирали конкретную.
- Если ничего похожего нет, выбор плеера не трогаем: включить чужую озвучку хуже,
  чем не сделать ничего.
- **Выключенные субтитры хранятся явно**, отдельно от «предпочтения нет»: иначе
  сработала бы штатная настройка «включать субтитры сразу» и их пришлось бы
  выключать каждую серию.
- Переключение повторяет последовательность штатной панели плеера
  ([panel.js:376](src/interaction/player/panel.js:376)): снять признаки со всех,
  поставить выбранной, вызвать её `onSelect` (через него переключается HLS).
  Видимость субтитров — через `PlayerVideo.subsview`.
- Момент переключения — события `tracks` и `subs` от `Lampa.PlayerVideo`: списки
  известны только после открытия файла. Параметры `track`/`sub` у `Player.play`
  не годятся, они принимают индексы.

**Хранилище — один ключ `watch_memory`**, запись на карточку `{q, v, r, a, s, t}`:
название, студия, разрешение, аудиодорожка, субтитры, время последнего обращения.
LRU на 200 записей, около 20 КБ, дальше не растёт. Запись перекладывается в конец
**и при чтении тоже**: `Storage.cache` вытесняет по порядку вставки, иначе давно
заведённый, но активно смотримый сериал вылетел бы первым. Старые ключи
`continue_last` и `audio_tracks` переносятся автоматически при первом запуске.

Общая с `continue.js` только **память**, не код: каждый плагин работает и без другого.

**Не проверено на webOS.** В плеере есть отдельная ветка `webosLoadTracks()`:
на телевизоре дорожками управляет нативный плеер, и механизм переключения там другой.
В браузере это не проверяется в принципе — `video.audioTracks` в Chrome не существует,
и события `tracks`/`subs` не приходят вовсе.

### continue.js — кнопка «Смотреть» на карточке

Запускает нужную серию из торрента без ручного выбора раздачи и файла.

Ключевые решения:

- Кнопка вставляется первой в `.full-start-new__buttons` — тогда она и визуально первая,
  и получает фокус по умолчанию (Lampa фокусирует первый `.selector`).
- Фильтры берутся из штатных фильтров карточки (`torrents_filter_data`), своего экрана
  настроек нет. Язык, HDR и Dolby Vision не ослабляются никогда; качество — только когда
  иначе играть нечего, и тогда пользователю показывается выбор.
- Поиск идёт **каскадом**: сначала запрос штатной кнопки торрентов, затем остальные
  названия тайтла, включая альтернативные из TMDB, — до первой непустой выдачи.
  Псевдонимы обязаны попадать и в проверку «тот ли это тайтл»: раздачу нашли по чужому
  названию, и названия карточки в её заголовке может не быть вовсе.
- Альтернативным названиям нужен признак `clarification`, иначе поиск дополнительно
  фильтруется по названиям карточки ([parser.js:302](src/core/api/sources/parser.js:302))
  и выдача гарантированно пустая. Проверено: «Суперглупцы» без него — 0 раздач, с ним — 4.
- Подпись пересчитывается не только на смене активности, но и на закрытии плеера:
  ни список файлов, ни плеер активностями не являются, это Modal поверх карточки,
  поэтому после просмотра серии событие `activity`/`start` не приходит.
- Приоритет: та же раздача, где смотрели прошлую серию → прежнее качество и студия
  по этому тайтлу → привычная студия из общего рейтинга → лучшее доступное качество.
- Воспроизведение идёт через `Lampa.Torrent.start` с перехватом события `torrent_file`
  (тип `render`) — своей цепочки TorrServer нет.
- Раздача помечается в `torrents_view` вручную: штатную пометку ставит компонент торрентов,
  который мы обходим.

Своё хранилище минимально: общий с `memory.js` ключ `watch_memory` и `continue_voices`
(рейтинг студий с затуханием, топ-30). Всё остальное — штатные `file_view`,
`torrents_view`, `torrents_filter_data`.
