# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Публичный репозиторий плагинов для [Lampa](https://github.com/yumata/lampa-source) —
медиацентра для ТВ. Здесь лежат **собранные** `.js`-файлы, которые Lampa загружает по URL.

Плагины пишутся под LG webOS, область — **только торренты** (онлайн-балансеры не используются).

## Как это подключается

Lampa хранит список плагинов в localStorage под ключом `plugins` — массив `{url, status}`.
Раздача идёт через **GitHub Pages** (ветка `main`, корень репозитория):

```
https://codecomplainer.github.io/lampa-plugins/<плагин>.js
```

**`raw.githubusercontent.com` использовать нельзя.** Проверено: raw отдаёт файл как
`content-type: text/plain` вместе с `x-content-type-options: nosniff`, поэтому браузер
отказывается исполнять его как скрипт — тег `<script>` завершается ошибкой, плагин
молча не загружается. Pages отдаёт `application/javascript`, и всё работает.

Репозиторий обязан быть публичным: у приватного Pages не работает, а raw требует токен.

Установка на телевизор — через плагин-менеджер (см. ниже), вводить адреса вручную не нужно.
Штатная «Удалённая конфигурация» Lampa для этого не подходит: она выдаёт пятизначный код
и умеет принимать команды `{type:'extension', url}`, но **отправляющей стороны нет** —
перебор `send`, `set`, `add`, `install`, `push` на `cub.rip/api/remote-configuration/`
даёт 404, реализован только приём.

## Разработка

Исходники, тесты и собранные бандлы живут в одном месте — здесь:

```
src/<имя>/<имя>.js      исходник, рядом вспомогательные модули и тесты
src/shared/             общий код нескольких плагинов
tools/build.js          сборка
<имя>.js                бандл в корне — его и раздаёт Pages
```

Цикл:

```bash
npm run dev -- <имя>    # пересборка при изменениях, ~1-3 с
npm test                # все тесты (сейчас 202 в 10 файлах)
npm run lint            # Biome
```

Собранный бандл кладётся сразу в два места:

```
./<имя>.js                              корень — отсюда публикуется на Pages
$LAMPA_SRC/build/web/plugins/<имя>.js   раздаваемый каталог рабочей копии Lampa
```

Второй нужен для проверки в браузере, локального режима менеджера и
`tv.js --deploy`. `LAMPA_SRC` по умолчанию `../lampa-source`; рабочей копии нет —
второй выход просто пропускается, на сборку для Pages это не влияет.

**Собранные `.js` обязаны оставаться в корне.** Pages раздаёт корень ветки, и
эти адреса уже лежат в `localStorage` телевизора, а адрес `manager.js` вводится
пультом руками. Любой перенос бандлов в подпапку отвяжет все установленные
плагины разом.

**Правка бандла в корне бессмысленна** — он перезаписывается следующей сборкой,
причём молча. От этого стоит хук `no-bundle-edit`, см. «Оснастка репозитория».

**Сборщик в репозитории один.** Раньше исходники лежали в рабочей копии Lampa, и
за один файл боролись два сборщика: watcher gulp следил в том числе за `plugins/`,
запускал полную цепочку на полторы-две минуты и в конце копировал `dest/<имя>/<имя>.js`
в `build/web/plugins/` ([gulpfile.js:184](../lampa-source/gulpfile.js:184)) — то есть
затирал свежий бандл своим, собранным до правки, уже посреди отладки. Бандл
регулярно оказывался устаревшим: то с вызовом функции без её определения, то
вообще без только что внесённой правки. Отладка шла по коду, которого в браузере
нет, — самый дорогой вид ошибки. Поэтому второго сборщика заводить нельзя, и
`plugin-dev.js` в рабочей копии Lampa удалён, а не оставлен про запас.

Push делать через PowerShell — из Bash git-авторизация не проходит.

## Соглашения

- **Conventional commits**, сообщения — **на английском**: `feat:`, `fix:`, `docs:`, `chore:`.
- Комментарии в коде — на русском, как в самой Lampa.
- Стиль кода Lampa: без точек с запятой, отступ 4 пробела, jQuery (`$`) как глобальный.
- Плагин обязан иметь защиту от повторной инициализации: `window.plugin_<имя>_ready`.
- Взаимодействие с приложением — только через глобальный `window.Lampa`.

## Общий код плагинов

`src/shared/` — то, что нужно нескольким плагинам сразу:

| Модуль | Зачем |
|---|---|
| `keys.js` | имена ключей хранилища |
| `match.js` | сопоставление аудиодорожек и субтитров |
| `watch.js` | заметить смену выбора, не трогая объекты плеера |

Сюда переезжает то, что нужно **обоим для одной и той же задачи**. Словарь
студий, например, не переехал: названия дорожек записывает memory, но толкует
их continue, и знание о студиях принадлежит ему одному.

Rollup инлайнит эти модули в каждый бандл, поэтому опубликованные файлы остаются
самодостаточными: **в рантайме плагины друг о друге не знают**, связь только на
уровне исходников. Каждый плагин обязан работать, даже если остальные не стоят.

Новая папка в `src/` подхватывается сама: сборка перебирает подпапки, Biome
и vitest ходят по `src` целиком. Перечислять её нигде не нужно.

## Ключи хранилища

Пространство `localStorage` у Lampa **плоское**: ни префиксов, ни namespace, ни
разделения по профилям. В нём лежат ~155 ключей ядра и ключи всех установленных
плагинов сразу.

Схема наших имён — **`cc_<плагин>_<что>`**, общие для нескольких плагинов
данные — `cc_watch_*`. Префикс не для красоты: `continue` и `manager` — обычные
английские слова, и чужой плагин, взявший те же имена, молча испортил бы данные.
Заодно всё наше находится и чистится одним грепом.

Единственное место, где имена записаны, — `src/shared/keys.js`.

**Кода миграции в плагинах нет.** Он был, отработал на всех устройствах и удалён:
держать разовый перенос вечно — значит вечно его и читать. Если схема поменяется
снова, миграция пишется заново и так же выбрасывается, когда сделает своё дело.

| Ключ | Что хранит |
|---|---|
| `cc_watch_memory` | память по тайтлу: memory пишет, continue и subpeek читают |
| `cc_watch_subs_lang` | последний выбранный язык субтитров, общий на все тайтлы |
| `cc_continue_voices` | счётчик запусков раздач по студиям, личный ключ continue |
| `cc_continue_probe` | уже проверенные раздачи |
| `cc_continue_no_cam` | отсекать ли экранки |
| `cc_manager_seen` | какие плагины менеджер уже предлагал |
| `cc_manager_source` | GitHub или локальный сервер |
| `cc_manager_local_host` | адрес машины разработчика |
| `cc_manager_on_<файл>` | переключатель плагина |

Три грабли, на которые легко наступить:

- **Подстроки `online_`, `file_view_` и `storage_` в имени запрещены.** Штатная
  «Очистка кэша» стирает ключ, если такая подстрока встречается где угодно
  внутри имени, а не только в начале
  ([storage.js:288](../lampa-source/src/core/storage/storage.js:288)).
- **`Storage.remove()` удаляет значение на сервере, а не в localStorage**
  ([storage.js:253](../lampa-source/src/core/storage/storage.js:253)). Локально
  удаляет только `localStorage.removeItem`, причём внутренний кэш `readed`
  сохранит старое значение до перезагрузки.
- **`Storage.field()` для незарегистрированного ключа возвращает строку
  `"undefined"`**, а она truthy: `defaults[name] + ''`
  ([params.js:509](../lampa-source/src/interaction/settings/params.js:509)).
  Для своих ключей — `Storage.get(key, default)`, либо регистрировать параметр
  через `SettingsApi.addParam`.

Синхронизация с CUB сама не включается: это белый список из шести ключей ядра, и
только для премиума. Наши данные ездят между устройствами лишь там, где `memory`
намеренно дублирует их в штатный `user_clarifys`.

Чужие ключи, которые мы читаем и не переименовываем: `plugins`, `user_clarifys`,
`torrents_view`, `torrents_filter`, `torrents_filter_data`, `file_view`,
`player_rewind`, `parse_lang`, `parser_use`, `language`.

## Кто за что отвечает

Граница проходит по моменту запуска файла:

- **continue** — что включить: подобрать раздачу и серию, проверив, что нужная
  озвучка в раздаче есть. Дальше плеера он не лезет; единственная его подписка
  на плеер — `destroy`, и та про подпись кнопки на карточке.
- **memory** — что выбрать внутри: аудиодорожка и субтитры, **при любом способе
  запуска** — хоть кнопкой continue, хоть через штатный экран торрентов.

Правило простое: **за плеером следит только memory.**

Но граница проходит не по месту наблюдения, а по смыслу. Наблюдать за выбором
дорожки — работа memory, а **толковать** название («ColdFilm — это студия») —
работа continue: только ему нужно понимать студии, чтобы подбирать раздачу.
Поэтому словарь студий лежит в continue, а не в общем коде, и рейтинг привычек
он считает сам при чтении: свои запуски раздач плюс названия дорожек из
`cc_watch_memory`, которые записала memory.

Так ни один плагин не работает на другого. Стоит поставить memory одну — она
просто помнит своё. Стоит одну continue — привычка учится по запускам, подбор
становится грубее, и только.

## Как плагины делят решения про звук и субтитры

Человек принимает **одно** решение — как он хочет это смотреть. Плагинов, которые
ему служат, несколько, и раньше каждый учился по-своему: continue помнил студию
из заголовка запущенной раздачи, memory — выбранную дорожку, и они не
разговаривали. Получалось, что continue продолжал подбирать русские раздачи
человеку, который явно переключился на английскую дорожку.

Свидетельства о выборе бывают разной силы, и веса должны это отражать:

| Сила | Что это | Где живёт |
|---|---|---|
| Прямое решение | выбрал дорожку или субтитры в панели | `a`, `s` + `so` |
| Наблюдение | запустил и досмотрел эту раздачу | `v`, `r` |
| Привычка | что обычно выбирает во всех тайтлах | `cc_continue_voices`, `cc_watch_subs_lang` |
| Ничего | — | лучшее доступное / не вмешиваться |

Отсюда правила, одинаковые для звука и субтитров:

- **Прямое решение побеждает наблюдение.** `continue/voice.js` предпочитает `a`
  полю `v`; `subpeek/choose.js` предпочитает выбор в этом файле записи по карточке.
- **Прямое решение весит больше в привычке.** Выбор дорожки добавляет в рейтинг
  студий втрое против запуска раздачи: раздачу выбирают за сидеров и качество,
  а студия там оказывается какой была.
- **Чужой язык снимает предпочтение, а не выворачивает его.** Если слушают не на
  языке поиска, значит слушают оригинал — он есть почти в любой раздаче, и
  держаться за прежнюю студию значит спорить с человеком.

**Момент записи — сам выбор, а не закрытие плеера.** События `destroy` не будет,
если телевизор выключили кнопкой или приложение сняли, и весь вечер пропадал.

Наблюдаем **со стороны**, на том же `timeupdate`, на котором Lampa обновляет
позицию просмотра ([player.js:137](../lampa-source/src/interaction/player.js:137)):
раз в три секунды сравниваем, что выбрано, с тем, что уже записано. Общий код —
`shared/watch.js`.

**Объекты плеера при этом не трогаем, и это выстрадано.** Была попытка подменять
у элементов списка `onSelect` — панель зовёт его после выбора, и поле выглядит
как оставленная для плагинов зацепка (ядро его только читает). На телевизоре это
**дважды подвесило список дорожек**: он схлопывался, а фокус оставался на нём, и
из плеера было не выйти. Причину поймать не удалось — исключений в консоли не
было. Менять чужие структуры ради удобства — плохой размен: цена ошибки тут не
«фича не сработала», а «телевизор завис».

Две тонкости наблюдения, обе стоили бы данных:

- **Первое наблюдение — точка отсчёта, а не решение.** В начале файла дорожку
  ставит плеер, и засчитывать её как выбор человека нельзя: рейтинг студий
  раздувался бы просто от того, что кино включили.
- **Реагируем только на смену.** Проверка идёт раз в три секунды, а событие
  возникает один раз — иначе один выбор весил бы столько, сколько длится фильм.

**Каждый плагин работает в одиночку.** Без memory поле `a` никто не пишет, и
continue откатывается на `v`, а привычку ведёт сам. Без continue поле `a` пишется,
и читать его просто некому. Проверять это правило надо при каждой такой связке —
данные общие, код нет.

## На какой сборке Lampa работает телевизор

**Телевизор крутит официальную Lampa с cub.red, а не нашу рабочую копию.** С машины
едут только плагины. Значит сверяться надо с тем кодом, который реально работает
на устройстве, — иначе отладка идёт по чужим исходникам, а это самый дорогой вид
ошибки: всё сходится, а на телевизоре не работает.

Поэтому **`../lampa-source` держим на коммите телевизора**, а не на HEAD апстрима:

```bash
git -C ../lampa-source checkout <коммит>   # отсоединённый HEAD, это нормально
git -C ../lampa-source checkout main       # вернуться к апстриму
```

Переключать стало дёшево: наших файлов там почти не осталось — исходники плагинов
переехали сюда. Что осталось (`tools/tv.js`, мост отладки, `.claude/`, `CLAUDE.*`),
перечислено в `.git/info/exclude`, поэтому переключение их не трогает. Правки
`gulpfile.js` переезжают вместе с рабочим деревом, если файл в обоих коммитах
одинаков — проверять так: `git diff --quiet <коммит> HEAD -- gulpfile.js`.

**Рабочая копия Lampa нужна для двух вещей и только для них:** читать код,
который реально крутится на телевизоре, и раздавать собранные плагины
через свой dev-сервер. Собирать плагины она больше не умеет.

**Lampa пишет дату сборки в консоль при каждом запуске.** Это и есть ответ:

```
App version: 3.2.8
App build date: 2026-07-21 12:32
App hash 03ccd57ccbb25ba4175be53e33ba4662
```

Строки печатает сама Lampa ([app.js:655-657](../lampa-source/src/app.js:655)),
подставляя `{__APP_BUILD__}` и `{__APP_HASH__}` при сборке. Читаются через
devtools:

```bash
node tools/tv.js --logs | grep "App build"
```

Дальше коммит — это последний, сделанный до этой минуты:

```bash
git -C ../lampa-source log --format='%h %ad %s' --date=format:'%Y-%m-%d %H:%M' --until='2026-07-21 12:32' -1
```

Так и определили: сборка от 21 июля 12:32, последний коммит до неё — `fd60928e`
(11:18). На нём и держим рабочую копию.

**Хеш — не коммит**, а отпечаток самой сборки; сопоставить его с git нельзя,
но он годится, чтобы заметить, что прошивка обновилась.

Если консоль недоступна, остаётся кружной путь: `Lampa.Manifest.app_digital` —
это версия без точек (`3.2.8` → `328`), она даёт окно в десятки коммитов, а
сузить его можно отпечатками поведения. Например, подписи аудиодорожек: до
`cc896aa5` они собирались через `' / '`, после — через `' · '`. Способ рабочий,
но нужен только когда devtools не поднять.

### Плагин обязан работать на обеих сборках сразу

Пин — это чтобы **читать** правильный код, а не чтобы под него подстраиваться.
Файл лежит на Pages один, cub.red обновляет прошивку когда захочет, и один и тот же
бандл должен работать и на сегодняшней сборке телевизора, и на завтрашней. Ветвлений
по версии в плагинах быть не должно.

Отсюда правило: опираться на то, что в этом промежутке **не менялось**, а
опору проверять в обоих коммитах, прежде чем на неё встать:

```bash
git -C ../lampa-source diff <старый> <новый> -- src/interaction/player/panel.js \
  | grep -E '^[+-].*(listener\.send|onSelect|\.selected|\.enabled|\.label)'
```

Что проверено на паре `fd60928e` (телевизор) и `1e8f2ce8` (HEAD апстрима):

| Опора | Состояние |
|---|---|
| `onSelect` у элементов списков | есть в обеих (`panel.js:387` и `:390`) |
| `selected` / `enabled` | не тронуты |
| Каналы `subsview`, `tracks`, `subs`, `webos_*` | не тронуты |
| `element.label` у дорожки | не тронут — берётся из контейнера |
| Подписи в панели | **переделаны**: `' / '` → `' · '`, плюс `tracksFromFfprobe` |

Последняя строка и есть иллюстрация правила: подписи менялись, поэтому
`match.describe` читает `label` самой дорожки, а не готовый `title` из панели.
Опирались бы на `title` — плагин сломался бы при первом же обновлении прошивки.

## Тесты

Тесты живут рядом с исходниками плагина (`src/<имя>/*.spec.js`, vitest).

**Названия фильмов и сериалов в тестах — вымышленные** (`Movie Name`, `Series Name`,
`Anime Title`). Настоящими остаются только названия студий озвучки: это справочные
данные, без них невозможно проверить распознавание.

Своя реализация разбора названий нужна потому, что штатный `TitleParser` Lampa
имеет три дыры, а править апстрим мы не можем: `CAMRip`/`TSRip` не распознаются,
кириллическая «х» в `03х01` даёт первый сезон вместо третьего, `HDR10+` не считается
за HDR.

```bash
npm test        # весь src, сейчас 202 теста в 10 файлах
```

## Оснастка репозитория

Хуки в `.claude/settings.json` работают сами, но знать о них надо заранее:

| Хук | Когда | Что делает |
|---|---|---|
| `no-bundle-edit` | перед правкой файла | **запрещает менять `.js` в корне** — это сборки, правка исчезнет при следующей и молча |
| `biome-on-save` | после правки | гоняет Biome по исходнику в `src/` |
| `lampa-index-refresh` | старт сессии | пересобирает реестр событий, если коммит Lampa сменился (~20 мс на проверку) |

Скилл **`lampa-api`** отвечает на вопрос «какое событие шлёт Lampa, что приходит
в payload и на какой шине оно живёт» — по реестру
`.claude/skills/lampa-api/references/events.md`. Реестр собирается разбором AST по
местам вызова `.send()`, то есть описывает не намерение, а факт. Пересобрать
вручную — `npm run index:events` (`tools/index-events.mjs`); обычно это делает хук.

Агент **`webos-compat`** проверяет изменения на совместимость с телевизором.
Запускать перед сборкой и публикацией: в браузере эти поломки не воспроизводятся,
а отладка на телевизоре стоит дорого.

**`tools/` — две разные папки, и в тексте они выглядят одинаково.**
`tools/build.js` и `tools/index-events.mjs` живут здесь; `tools/tv.js` и мост
отладки — в `../lampa-source`.

## Как добавить новый плагин

### 1. Исходники

Создать `src/<имя>/<имя>.js`. **Имя файла обязано совпадать с именем папки** —
так устроена сборка. Рядом кладутся вспомогательные модули и тесты.

Скелет:

```js
function startPlugin(){
    if(window.plugin_<имя>_ready) return   // защита от повторной инициализации

    window.plugin_<имя>_ready = true

    // регистрация кнопок, экранов, настроек
}

Lampa.Lang.add({
    <имя>_title: {ru: '…', en: '…', uk: '…'}
})

if(window.appready) startPlugin()
else Lampa.Listener.follow('app', (e) => { if(e.type === 'ready') startPlugin() })

export default {}
```

Полезно вынести отладочный доступ: `window.__<имя> = {…}` — тогда логику можно
прогонять на живых данных прямо из консоли браузера, не пересобирая.

Чистые функции (разбор, отбор, решения) держать в отдельных модулях и покрывать
тестами; в основном файле оставлять UI и оркестрацию.

### 2. Сборка и проверка

```bash
npm test
npm run build -- <имя>    # без имени соберёт все
```

Линт и форматирование — [Biome](https://biomejs.dev):

```bash
npm run lint      # проверить
npm run format    # исправить и отформатировать
```

Несколько правил отключено осознанно, это не небрежность:

| Правило | Почему выключено |
|---|---|
| `useConst` | в самой Lampa везде `let`, плагины должны читаться как её код |
| `noAssignInExpressions` | `if((m = str.match(…)))` — обычная идиома разбора регулярками |

Форматирование Biome ставит пробел после `if` и `function` — это расходится
со стилем Lampa (`if(...)`), но отключить нельзя. Приняли как плату за
единообразие внутри плагинов.

Собранный бандл всегда соответствует исходникам: сборщик в репозитории один,
и исходники лежат рядом с ним, а не в чужом рабочем дереве. См. «Разработка».

Проверка в браузере (параметр `v` обходит кеш):

```js
localStorage.setItem('plugins', JSON.stringify([
    {url: 'http://localhost:3000/plugins/<имя>.js?v=' + Date.now(), status: 1}
]))
```

Проверять **до** публикации: на телевизоре отлаживать несравнимо дольше.

### 3. Публикация

Копировать больше нечего — `npm run build` уже положил бандл в корень. Остаётся
добавить запись в `plugins.json`, иначе плагин не появится в менеджере:

```json
{"file": "<имя>.js", "name": "Короткое название", "descr": "Что делает"}
```

Необязательные поля:

| Поле | Смысл |
|---|---|
| `replaces` | имена файлов, которые этот плагин заменяет — переименование переезжает само |
| `default` | `false` — не ставить автоматически при появлении в манифесте |
| `local` | `true` — бандл не кладётся в корень и раздаётся только с машины разработчика |

`name` и `descr` видны на телевизоре в разделе «Мои плагины», поэтому пишутся
для пользователя, а не для разработчика. Сам `manager.js` в манифест не вносится —
см. раздел о менеджере ниже.

Коммит и `git push` **через PowerShell**. GitHub Pages обновляется не мгновенно —
обычно до минуты. Проверить, что раздача поднялась и MIME правильный:

```bash
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" \
  https://codecomplainer.github.io/lampa-plugins/<имя>.js
```

Должно быть `200 application/javascript`. Если `text/plain` — значит адрес указывает
на raw, и плагин не запустится.

На телевизоре ничего вводить не нужно: менеджер подтянет новый плагин из манифеста
сам, останется включить переключатель.

## Плагины

### manager.js — менеджер плагинов

Единственный плагин, адрес которого приходится вводить на телевизоре. Дальше все
остальные включаются переключателями в настройках, раздел «Мои плагины».

- Список берётся из `plugins.json` в корне репозитория — новый плагин появляется
  на телевизоре сам, достаточно добавить строку в манифест. Манифест перечитывается
  при каждом заходе в настройки; момент — открытие **главного** экрана настроек,
  а не нашего раздела: параметры раздела собираются при его создании, и
  перерисовывать их, когда он уже на экране, поздно.
- Список плагинов приводится в соответствие манифесту: новый ставится сам,
  переименованный переезжает по `replaces` (и только если старый стоял — иначе это
  была бы установка без спроса), исчезнувший удаляется. Трогаются только свои адреса:
  плагины, добавленные мимо менеджера, не наше дело.
- Ключ `cc_manager_seen` помнит, что менеджер уже предлагал. Без него пришлось бы выбирать
  между «новые плагины не появляются» и «выключенные возвращаются при каждом запуске».
- Названия для штатного экрана «Расширения» проставляются из манифеста в поле `name`
  записи плагина — Lampa показывает именно его, а плагин, добавленный по адресу,
  приходит без названия, и список превращается в набор одинаковых «Без названия».
  Поле обычное, сама Lampa даёт задать его вручную ([extension.js:73](../lampa-source/src/interaction/extensions/extension.js:73)).
- Манифест запрашивается с повторами: телевизор запускает приложение раньше, чем
  поднимается сеть, и единственная попытка проваливается молча — выглядит это так,
  будто плагины без названий, а новых просто нет. Ошибка пишется в консоль.
- Переключатель источника **GitHub / локальный сервер**: в локальном режиме плагины
  грузятся с машины разработчика (`http://<ip>:3000/plugins/`), что позволяет проверять
  свежую сборку на телевизоре без публикации. Режим проверен целиком: плагин реально
  загружается с локального адреса и работает.
- Под каждым плагином показан фактический адрес загрузки.

**Сам менеджер в `plugins.json` не добавляется намеренно.** Иначе его можно выключить
переключателем и остаться без доступа к остальным плагинам — вернуть их можно будет
только вводом адреса пультом.

### Как раздать плагины на телевизор со своей машины

Отдельный сервер поднимать не нужно: раздаёт тот же `npm run start` в рабочей копии
Lampa. Browser-sync слушает на всех интерфейсах, поэтому `build/web/plugins/` виден
из домашней сети.

1. Собрать нужные плагины — они сразу попадают в раздаваемый каталог:

    ```bash
    npm run build -- <имя>
    ```

2. Проверить, что телевизор достучится. Адрес именно машины в локальной сети,
   не `localhost`:

    ```bash
    curl -s -o /dev/null -w "%{http_code} %{content_type}\n" http://<ip>:3000/plugins/<имя>.js
    ```

    Ожидается `200 application/javascript`. Пусто — почти всегда брандмауэр Windows
    на порту 3000. В строке browser-sync «External» может стоять адрес постороннего
    адаптера (VPN, Radmin), нужен домашний.

3. На телевизоре один раз: Настройки → Мои плагины → **Адрес локального сервера** →
   `<ip>:3000`. Дальше либо переключить **Источник** на «Локальный сервер» — тогда
   оттуда грузится всё, — либо оставить GitHub: плагины с пометкой `local` в манифесте
   всё равно поедут с машины разработчика, потому что в репозитории их нет.

С ноутбука то же самое делается не вставая: `node tools/tv.js --local` переводит все свои
плагины на локальные адреса, `--github` возвращает, `--deploy <имя>` делает это для одного
плагина вместе со сборкой, перезапуском и ожиданием загрузки.

**Манифест всегда читается из репозитория**, даже в локальном режиме, — совсем новый
плагин сначала должен появиться в `plugins.json` здесь.

**В конце вернуть телевизор на GitHub** (`node tools/tv.js --github`), иначе при
выключенном ноутбуке он останется без плагинов.

**Про локальные адреса.** `addPluginParams` ([plugins.js:148](../lampa-source/src/core/plugins.js:148))
пропускает всю обработку для URL с IP-адресом. Отсюда два следствия:

- `Utils.rewriteIfHTTPS` к таким адресам не применяется, поэтому локальный режим
  переживает ситуацию, когда сама Lampa открыта по https — иначе адрес переписался бы
  и сборка перестала грузиться;
- но и `reset=Math.random()` не добавляется, то есть штатного обхода кеша нет.
  Dev-сервер отдаёт `Cache-Control: max-age=0` с ETag, поэтому в браузере свежая сборка
  подхватывается. Если на webOS правки перестанут появляться после пересборки —
  причина в кеше, и нужно добавлять метку версии к локальным адресам.

Порядок важен: автоустановка выполняется **до** отрисовки настроек, иначе переключатель
запомнит состояние «выключен», которое было до установки. Значение переключателя при
каждой отрисовке приводится к факту (`Lampa.Storage.set`), потому что плагин могли
добавить или удалить мимо менеджера.

### memory.js — память просмотра

Тайтл включается так же, как в прошлый раз: по тому же названию, с той же
озвучкой и теми же субтитрами. Работает при любом запуске плеера и на обычном
экране торрентов, а не только через кнопку `continue.js` — поэтому отдельный плагин.

**Название для поиска.** Название карточки и трекерное совпадают не всегда:
корейский сериал «Суперчудаки» (원더풀스) лежит на трекерах как «Суперглупцы»,
и ни одно из названий карточки не находит ничего. Плагин подставляет запомненное
название в штатный экран торрентов на событии `activity`/`init` — оно приходит
после создания компонента, но до начала поиска.

- Запоминается по факту **запуска файла**, а не удачного поиска: «нашлось»
  и «это то, что нужно» — разные вещи.
- Хранится только нестандартное название: то, что и так строится из карточки,
  занимало бы место впустую.
- Дублируется в штатный `user_clarifys` — он синхронизируется через CUB и читается
  обычным списком уточнения ([filter.js:36](../lampa-source/src/interaction/filter.js:36)), поэтому
  правильное название всплывает первым и на другом устройстве. Заодно карточка
  подрезается до пяти запросов: штатный код пишет туда без ограничений.
- Если своей записи ещё нет, берётся последнее, что человек вводил руками.

**Озвучка и субтитры.**

- Дорожки сопоставляются по языку и названию, **не по индексу**: в одной раздаче
  русская дорожка первая, в другой третья.
- Совпадение названия озвучки важнее языка — «Дубляж» и «LostFilm» обе русские,
  но выбирали конкретную.
- **Названия дорожек даёт не плеер, а чужой плагин `tracks`** с cub: он читает
  метаданные и дописывает `label` прямо в объекты дорожек
  (`../lampa-source/plugins/tracks/tracks.js:230` — чужой плагин, лежит там).
  Он может быть не установлен или отвалиться —
  у нас так и вышло, когда умер домен `cub.red`, — и тогда от дорожки остаётся
  один язык, а двух русских озвучек это не различает.
- Поэтому запоминается ещё и **номер дорожки вместе с приметами списка**
  (`a.i` и `a.k`, где `k` — языки по порядку, например `ru,ru,en`). Номер
  применяется, только если список совпал: тот же набор языков в том же порядке
  означает тот же файл. Разошлось — номеру верить нельзя, остаётся язык.
  Название, если оно есть, всегда важнее номера: оно переносится между раздачами,
  а номер — нет.
- Если ничего похожего нет, выбор плеера не трогаем: включить чужую озвучку хуже,
  чем не сделать ничего.
- **Выключенные субтитры хранятся явно**, отдельно от «предпочтения нет»: иначе
  сработала бы штатная настройка «включать субтитры сразу» и их пришлось бы
  выключать каждую серию.
- Переключение повторяет последовательность штатной панели плеера
  ([panel.js:376](../lampa-source/src/interaction/player/panel.js:376)): снять признаки со всех,
  поставить выбранной, вызвать её `onSelect` (через него переключается HLS).
  Видимость субтитров — через `PlayerVideo.subsview`.
- Момент переключения — события `tracks` и `subs` от `Lampa.PlayerVideo`: списки
  известны только после открытия файла. Параметры `track`/`sub` у `Player.play`
  не годятся, они принимают индексы.

**Хранилище — один ключ `cc_watch_memory`**, запись на карточку
`{q, v, r, h, a, s, so, t}`: название, студия, разрешение, раздача,
аудиодорожка, субтитры, время последнего обращения. У `a` внутри —
`{l, n, i, k}`: язык, название, номер в списке и приметы самого списка.

**`s` и `so` — два разных вопроса, и это важно.** `so` отвечает «включены ли
субтитры», `s` — «какие именно выбирали». Раньше это было одно поле, и выключение
стирало память о дорожке: `s` становилось `false`. Из-за этого subpeek не знал,
что показывать при перемотке, — а не знать было нормальным состоянием, потому что
смотрят обычно без субтитров. Теперь выключение пишет только `so`, а `s`
переживает его.

LRU на 200 записей, около 20 КБ, дальше не растёт. Запись перекладывается в конец
**и при чтении тоже**: `Storage.cache` вытесняет по порядку вставки, иначе давно
заведённый, но активно смотримый сериал вылетел бы первым.

Общая с `continue.js` только **память**, не код: каждый плагин работает и без другого.

**Не проверено на webOS.** В плеере есть отдельная ветка `webosLoadTracks()`:
на телевизоре дорожками управляет нативный плеер, и механизм переключения там другой.
В браузере это не проверяется в принципе — `video.audioTracks` в Chrome не существует,
и события `tracks`/`subs` не приходят вовсе.

### subpeek.js — субтитры при перемотке назад

Не расслышал реплику — отмотал — прочитал, как на Apple TV. Короткая перемотка
назад включает субтитры ровно на срок штатного шага `player_rewind` и гасит их сама.

**Срок считается по таймлайну плеера, а не по часам.** Субтитры держатся, пока
воспроизведение не пройдёт положенные секунды от того места, куда попали. Часы
здесь врут: на паузе они идут, а фильм стоит, и субтитры погасли бы у человека,
который отмотал и задумался. Замедление и прыжок вперёд ломали бы отсчёт так же.
Поэтому гашение висит на `timeupdate` — он и приходит ровно тогда, когда кино
действительно идёт. Новая перемотка не продлевает прежний отрезок, а назначает
новый от текущей позиции.

**Удержание кнопки исключено.** Отдельного режима «удержание» в Lampa нет: это
поток `keydown` от автоповтора ОС, троттлится до десяти в секунду
([keypad.js:51](../lampa-source/src/core/keypad.js:51)), шаг копится с ускорением
×1.03, а настоящий seek случается один раз через 1000 мс после отпускания
([video.js:1349](../lampa-source/src/interaction/player/video.js:1349)). Отличить
удержание от серии тычков можно только по **отсутствию `keyup`** между нажатиями —
счёт нажатий не годится, три быстрых тычка дают тот же результат, что треть
секунды удержания.

**Вопрос задаётся между соседними перемотками, а не «был ли автоповтор вообще».**
Глобальный признак копится с обычной навигации по меню: к моменту, когда человек
дойдёт до плеера и нажмёт «влево», он давно взведён, и вспышки не будет никогда.
На телевизоре получилось именно так — `burst` показывал `repeated: true` при
закрытом плеере. Запасной признак для кнопок панели и мыши, где `keyup` не
приходит вовсе, — промежуток короче 180 мс.

Наблюдаем, не патча ядро: `rewindStart` шлёт `Lampa.PlayerVideo.listener` `rewind`
на каждый вызов ([video.js:1382](../lampa-source/src/interaction/player/video.js:1382)).
Клик и свайп по таймлайну зовут `Video.to` и этого события не шлют — большие
прыжки мышью отсекаются сами. Направление и величина берутся по факту, из позиции
до и после: сложить их из числа нажатий нельзя.

**Дорожка не угадывается по языку интерфейса** — он говорит, на каком языке меню,
а не на каком человек читает субтитры. Отбор вынесен в `choose.js` и покрыт
тестами, три источника по убыванию точности:

1. что включали руками за это воспроизведение — ловится на `PlayerPanel`
   `subsview`, где `selected` выставлен до отправки события;
2. запись memory по карточке (`cc_watch_memory`, поле `s`) — **независимо от
   `so`**: нас интересует «какие», а не «включены ли»;
3. последний язык субтитров вообще (`cc_watch_subs_lang`) — тогда годится любая
   дорожка на нём.

Ничего не нашлось — вспышки не будет. Без третьего источника фича оказывалась
почти недостижимой: смотрят обычно без субтитров, и знать дорожку было неоткуда.

**На webOS `Lampa.PlayerVideo.subsview()` бесполезен** — он прячет DOM-слой Lampa,
а нативные субтитры рисует прошивка поверх видеоплоскости. Единственная доступная
извне ручка — сеттер `mode` у элементов из `webos_subs`
([webos.js:76](../lampa-source/src/interaction/player/webos.js:76)); выключением
служит псевдострока `index:-1`. Идти надо именно через него: внутри `webos.js`
живёт приватный `subtitle_visible`, который `rewinded()` переустанавливает после
каждой перемотки — свой luna-вызов был бы погашен через секунду.

Ветка выбирается по факту прихода `webos_subs`, а не по `Lampa.Platform`: на том же
телевизоре нативный путь не включается, если источник отдал `voiceovers`
([video.js:979](../lampa-source/src/interaction/player/video.js:979)).

Две вещи, без которых плагин ломает соседей:

- **Вспышка обязана вернуть `mode='disabled'` за собой.** memory на закрытии плеера
  считает дорожку выбранной в том числе по `mode === 'showing'`, и решила бы, что
  человек смотрит с субтитрами — со следующей серии они включались бы сами.
- **Гасим по каналу `back` у `Lampa.Keypad`**, который уходит в шину раньше, чем
  keypad зовёт `Controller.back()` ([keypad.js:178](../lampa-source/src/core/keypad.js:178)).
  Порядок подписчиков `Player.destroy` зависит от порядка загрузки плагинов и не
  управляется, так что на него полагаться нельзя.

Ручной выбор субтитров во время вспышки её отменяет, но ничего не переключает:
человек мог их только что включить.

**Проверено на webOS** через `devtools.js`: `webos_subs` приходит дважды (штатный
цикл пересоздания видео), список содержит псевдострочку `index:-1` и реальные
дорожки, `keyup` от пульта приходит исправно и парами. Вспышка отрабатывает.

### continue.js — кнопка «Смотреть» на карточке

Запускает нужную серию из торрента без ручного выбора раздачи и файла.

Ключевые решения:

- Кнопка вставляется первой в `.full-start-new__buttons` — тогда она и визуально первая,
  и получает фокус по умолчанию (Lampa фокусирует первый `.selector`).
- Фильтры берутся из штатных фильтров карточки (`torrents_filter_data`), своего экрана
  настроек нет. Язык, HDR и Dolby Vision не ослабляются никогда; качество — только когда
  иначе играть нечего, и тогда пользователю показывается выбор.
- Поиск идёт **каскадом**: сначала запрос штатной кнопки торрентов, затем остальные
  названия тайтла, включая альтернативные из TMDB, — до первой непустой выдачи.
  Псевдонимы обязаны попадать и в проверку «тот ли это тайтл»: раздачу нашли по чужому
  названию, и названия карточки в её заголовке может не быть вовсе.
- Альтернативным названиям нужен признак `clarification`, иначе поиск дополнительно
  фильтруется по названиям карточки ([parser.js:302](../lampa-source/src/core/api/sources/parser.js:302))
  и выдача гарантированно пустая. Проверено: «Суперглупцы» без него — 0 раздач, с ним — 4.
- Подпись пересчитывается не только на смене активности, но и на закрытии плеера:
  ни список файлов, ни плеер активностями не являются, это Modal поверх карточки,
  поэтому после просмотра серии событие `activity`/`start` не приходит.
- Приоритет: та же раздача, где смотрели прошлую серию → прежнее качество и студия
  по этому тайтлу → привычная студия из общего рейтинга → лучшее доступное качество.
- **«Та же раздача» опознаётся по хешу**, который парсер отдаёт в выдаче, — он же
  лежит в поле `h` записи по карточке. Раньше тут был только замысел: в коде
  раздача угадывалась по совпадению студии и качества, и на живом сериале это
  уводило на чужой релиз. Штатная пометка `viewed` не заменяет хеш: она общая на
  все тайтлы, без порядка и без привязки ([parser.js:286](../lampa-source/src/core/api/sources/parser.js:286)),
  то есть отвечает «эту раздачу когда-то открывали», а не «эту смотрели здесь».
  Осталась запасным признаком — не все трекеры отдают `hash`.
- Мёртвые раздачи отсекаются целиком (`!cand.seeders` → мимо), а среди живых
  число раздающих даёт до 50 баллов — тайбрейкер между равными, не критерий:
  500 сидеров не делают экранку лучше рипа.
- Воспроизведение идёт через `Lampa.Torrent.start` с перехватом события `torrent_file`
  (тип `render`) — своей цепочки TorrServer нет.
- Раздача помечается в `torrents_view` вручную: штатную пометку ставит компонент торрентов,
  который мы обходим.

Своё хранилище минимально: общий с `memory.js` ключ `cc_watch_memory` и `cc_continue_voices`
(рейтинг студий с затуханием, топ-30). Всё остальное — штатные `file_view`,
`torrents_view`, `torrents_filter_data`.

### devtools.js — отладка телевизора с ноутбука

На webOS нет ни консоли, ни отладчика, а половина поведения — нативный плеер,
аудиодорожки — в браузере не воспроизводится вовсе. Плагин открывает канал
к dev-серверу и работает в паре с мостом `tools/tv-bridge.js`.

**Инициатива у телевизора намеренно.** Снаружи в него не постучаться, поэтому
он сам спрашивает, нет ли для него выражения, выполняет его и возвращает
результат; заодно шлёт накопленную консоль. Так работает и через NAT, и без
вебсокетов, которых на старых webOS может не быть. Адрес dev-сервера плагин
вычисляет из собственного адреса загрузки — настраивать нечего.

**Исходник публичный, бандл — нет.** Плагин выполняет присланный код, но опасен
не исходник (секретов в нём нет), а собранный файл, подключённый с чужого адреса.
Защит три, и они не пересекаются:

- `isLocal(HOST)` — канал поднимается только на петлю, домашнюю сеть или
  `.local`; с любого другого адреса молча выключается;
- `local: true` в `plugins.json` — сборка по этой пометке **не кладёт бандл
  в корень**, то есть на Pages он не попадает никогда;
- `/devtools.js` в `.gitignore` — закрывает и ручное копирование в корень.

Плюс `default: false`: сам не ставится, включается переключателем.

Команды — `tools/tv.js` в рабочей копии Lampa:

```bash
node tools/tv.js "Lampa.Manifest.app_digital"   # выполнить выражение
node tools/tv.js --logs                         # консоль с прошлого запроса
node tools/tv.js --status                       # подключён ли телевизор
node tools/tv.js --reload                       # перезапустить Lampa
node tools/tv.js --local / --github             # чем кормить телевизор
node tools/tv.js --deploy <имя>                 # сборка, переключение, ожидание загрузки
```
